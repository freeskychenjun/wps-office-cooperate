**版本 v1.37（2026-11-05）**：**接管提示可整体关闭（A/B 自证）+ 窗口写入可追溯（trace）+ "关闭慢/重开空白"的诊断口径**。用户 m01182 认为卡死是 v1.35/v1.36 的撤标记改造引入的，因此本版不再论证而是给可自证的工具。
- **对照实验（本次定性的依据）**：① 在**零 helper 进程**（`EtHelper`/`WpsHelper`/`WppHelper` 计数 0）下，双击 xlsx 让 WPS 在已运行实例上交接，仍复现 `wps.exe` 崩 `kprometheus.dll_unloaded` 0xc0000005（11-05 21:41:44、21:42:35，PID 0x987c/0xb908）⇒ 打开交接崩溃不需要我们的标记参与；② scratch 工作簿"带标记关闭 + 租约到期撤标记"：关闭 428/687 ms、`releaseHints()` 30/203 ms、期间 0 崩溃；③ 复现用户口中的卡死形态：脏文档关闭被晾住后，窗口仍显示文件名但 `Application.Workbooks.Count == 0`（`close` 报 `NOT_OPEN`）⇒ 僵尸窗口，只能结束 `wps.exe` 重开。
- **`hint-off` 总开关**：`WOC_HINT_OFF=1` 或文件 `%LOCALAPPDATA%\wps-office-cooperate\hint-off.txt` ⇒ 三端不写任何自动 UI（`open` 不写前缀、`hint` 返回 `disabled:true`、`EnsureHint`/`EnsureTitleMarker` 跳过、`ReleaseHints` 跳过、`HealWindow` 也跳过），`hint -Clear` 永不禁用；用于 A/B 判定"卡死是否与标记有关"。
- **`trace` 日志**：`WOC_TRACE=1` 或 `trace-on.txt` ⇒ 追加 `%LOCALAPPDATA%\wps-office-cooperate\trace-<app>.log`（`release start/done/skipped`、`heal skipped`、`hint skipped`，毫秒时间戳）。实现于 `shared/HintLease.cs` 的 `HintOff()` / `Trace()`，三端 `HintOnTakeover`/`EnsureHint`/`ReleaseHints`/`HealWindow`/`HintCmd` 各加保护。
- **诊断口径写进 SKILL 当前版本**：`app.visible=false`+`workbooks>0` ⇒ 窗口隐藏（下条命令自愈）；`workbooks:[]` 但窗口仍显示文件名 ⇒ 僵尸窗口（杀 wps 重开）；`close` 报 `NOT_OPEN` 但窗口还在 ⇒ 同上。
- **实测**：`hint-off.txt` 下 `open` 返回 `hint.disabled:true`、标题无前缀、`status.hinted=false`、`read` 正常。

**版本 v1.36（2026-11-05）**：**不留残余客户端 + 卡死窗口自愈（修"关闭接管的 Excel 半天才关、重开一片空白"）**。用户反馈（pi agent 实测）：关闭被接管的 `毛坊湖高程点.xlsx` 要等到像卡住，再打开就成"卡死"状态。

- **① 隐藏窗口自愈**：三端 `HandleRequest` 在 `EnsureHint` 之前先 `HealWindow()`——`_app.Visible == false` 且文档数 >0 时 `Visible = true` + 激活活动文档/窗口（Excel `ActiveWorkbook.Activate()`、Word `ActiveDocument.Activate()`、PPT 无窗口先 `NewWindow()` 再 `Windows(1).Activate()`），stderr 记 `repaired a hidden ... window (v1.36)`。⇒ **AI 下一条命令（甚至 `status`/`read`）就把"卡死"窗口恢复**，用户不必手动关开。
- **② 租约到期 helper 直接退出**：`shared/PipeServer.cs` 的 lease-stale 分支原来是"release 后继续等 20 min"，现在 `releaseHints()` 之后 `return 0`（日志 `hint lease expired ... exiting`）；`finally` 只在 `!released` 时兜底 release（避免往半死的 WPS 再发 COM）。⇒ agent 走了 helper 也走，用户随后自己保存/关闭**没有残余自动化客户端**。
- **③ 陈旧 COM 引用自恢复**：`App()` 复用缓存前用 `StillAlive()` 轻量探针（`Workbooks/Documents/Presentations.Count`）；只有 `RPC_E_DISCONNECTED 0x80010108`/`CO_E_OBJNOTCONNECTED 0x800401FD`/`0x800706BA`/`MK_E_UNAVAILABLE 0x800401E3` 判死并重连，其它异常（busy）不动健康对象。`close` 关最后一份文档 `Quit()` 后与 `quit` 之后均 `_app = null`（Word 原本已有）。
- **④ 包装层自动补起 helper**：`scripts/<app>.ps1` 在发请求前 `Start-Daemon`（ping 命中 ~ms、未命中才 `Start-Process`），因 helper 现在会随租约退出——**暂停很久的会话下一条命令仍走常驻快路径**，不静默退化成一次性慢路径。

**版本 v1.35（2026-11-05）**：**接管标记改为租约——修"退出 AI 会话后文档仍显示被接管"（用户反馈的真缺陷）**。现场取证：16:52 打开的 `WorkBuddy水文分析实战运用汇报-溪霞水库.pptx` 到 17:30 仍顶着「〔AI接管中〕」窗口前缀（`wps.exe` PID 实读），`WppHelper.exe --serve` 还活着，但已无 agent 命令；旧的还原路径（`finish` / `close` / `hint -Clear`）全部要求 agent 主动调用，会话一断就永远没人清，`status` 里也只能看到标记一直挂着。
- **根因**：接管提示只有"显示"没有"生命周期"。`open` 打标记是纯窗口状态（正确，不写文件），但标记的存活期等于"直到有人来清"，而唯一会来清的就是 agent 自己。托盘图标最多 4 h 自灭、文档关闭自灭，标题/状态栏/PPT 标题前缀则**无任何上限**。
- **修法：租约（lease），不是定时器也不是退出钩子**。新增 `scripts/helper/shared/HintLease.cs`：常驻 helper（三端）在启动时与**每条命令服务完之后**把 `%LOCALAPPDATA%\wps-office-cooperate\hint-lease-<app>.txt` 刷成当前毫秒；`PipeServer.Run` 等请求从"一次 `WaitOne(20 min)`"改成**≤5 s 的切片轮询**，切片到点时若 `now - lease > WOC_HINT_LEASE_MS`（默认 **120 s**）就调用该 app 的 `releaseHints()`；同时 `Run` 用 `try/finally` 包住主循环，**任何退出路径**（20 min 空闲、`serve -Action stop`、最后一份文档关闭、循环内异常）都再 release 一次。⇒ 标记不可能比进程活得久，而进程又不可能比"没有命令"活得久。
- **显示与意图分离（这是"AI 回来时还能补标"的关键）**：`releaseHints()` 只撤**看得见的标记**（Word/Excel：逐文档把 caption 还原成 `Name`、清状态栏；PPT：`ApplyTitleMarker(p,false)` + `ApplySlideMark(p,false)` 撤页内药丸 + `MarkStateClear` 防止误触发 `badgeRepaired`），**不动接管意图**（Word/Excel 新增 `hint-state-<app>.json`：路径→tag；PPT 沿用 `ppt-title-hint.json`）。每条命令开头的 `EnsureHint`（Word/Excel 新增，PPT 本就有 `EnsureTitleMarker`）发现 caption/标题又没标记了就把标记补回。显式收尾（`finish`/`close`/`hint -Clear`/`open -NoHint`）才清意图，之后不再自动补标。`save -As` 同步迁移意图键（旧路径→新路径）。
- **默认参数与逃生口**：`WOC_HINT_LEASE_MS` 环境变量可调（≥2000 ms；测试用 4000 ms），默认 120 s 是"AI 思考/用户阅读"与"人已离开"的折中；`WOC_NO_DAEMON=1` 一次性模式没有常驻进程跑轮询，仍只靠显式收尾（文档中已注明）。
- **验收（三端实测 + 回归）**：新增 `tests/word/check_hint_lease.py`、`tests/excel/check_hint_lease.py`、`tests/ppt/check_hint_lease.py`：把租约调到秒级（Word/Excel 4 s、PPT 8 s——标题探针 = PowerShell + Add-Type 约 2 s/次，4 s 会两次探针之间就过期）后断言"open 带标记 → 静默 9/18 s → `status`/窗口标题无标记 → 下一条命令 → 标记回来 → `serve stop` → 立即无标记 → `finish` → 意图文件删键"；既有 `tests/*/check_hint.py`、`tests/word/check_daemon.py`、`tests/*/check_tray.py`、`tests/check_encoding.ps1` 全过（**`check_daemon` 的 PPT D4 在本机会因用户自己开着一份演示文稿而报 `running:true`**：`presentationsLeft:1` 就是那份用户的稿，daemon 的"最后一份关闭才退出"规则本身正确，Word/Excel 同一条共享代码 D4 通过）。**现场修复**：用户那份 deck 的残留前缀在同一次部署后由 lease release 清掉，文件 size/mtime 未变（从未保存）。
- **文档**：`SKILL.md` 新增「自动还原（v1.35 租约）」并更新 `serve`/三端 `hint` 速查行；`reference/workflows.md` §14 补租约小节；本条目即版本单源。

**版本 v1.33（2026-11-03）**：**Word 表格一键整备：`table -Action plan` + `table -Action normalize` + `render -Table`**。起因是同日中午的会话 `session-a305706b`：一份 29 页 / 14 表的水利自检报告做「题注编号修正 + 表名外提 + 全表加粗边框」，三类小事用了 **127 次工具调用 / 88.6 分钟**。本次把探索/返工压成 1–2 条命令，并把两个真实缺陷在命令内部修掉。
- **取证（会话日志 token 级归因）**：第 2 轮墙钟 88.57 min → **模型 79.68 min（89.96%）**、工具 8.84 min（9.98%）；其中 **TTFT 57.79 min（65%）**，每步 prompt 均值 21.8 万 token、末步 34.8 万；TTFT 与 prompt 大小相关系数 **0.834**（<150k 均值 4.6 s，>300k 均值 60 s，峰值 94 s）。127 次调用里 **56 次（42.2 min）是试错绕路**，66 次（44.1 min）本可被 plan/normalize/render 吸收；反事实推算 **127 次→6 次、88.6 min→约 3.5 min（25–28×）**，前提是同时守住上下文纪律。⇒ 瓶颈不是 COM 慢，而是「步数 × 每步上下文」。

**版本 v1.12（2026-10-30）**：`hint -Tray` —— **常驻托盘图标**。v1.11 的三个信号各有短板：标签页标记常驻但**不带进度**、气泡**一过性**、Writer 状态栏**不渲染**，于是补一个托盘图标：橙色「AI」小圆标，**悬停 = 标记 + 当前步骤**（「〔AI接管中〕 报告.docx · 正在核对第 3 节」），**右键 = 「结束协作：还原标题标记」/「仅关闭托盘图标」**；`finish` / `close` / `hint -Clear` 让它自动退出，忘了也会在 **4 小时**后自灭。实现上**不新增常驻服务**：`hint -Tray` 由短命 helper 写一个状态文件，再用**自己这个 exe 以 `--tray` 重开一份**（只跑消息循环、不发 COM 请求），状态文件就是唯一 IPC；菜单里的「还原」直接调用本 skill 的 `hint -Clear`，所以 daemon 不必懂 COM，三个 app 共用一份 `scripts/helper/shared/Tray.cs`。两个实测坑：① spawn 必须 `UseShellExecute=true`，否则子进程继承调用方 stdout 管道，任何读到 EOF 的调用方（python `subprocess.communicate`、PowerShell 管道）会被图标的 4 小时寿命**卡死**；② Windows 把新托盘图标默认收进「^」溢出区，进程无法自我提升，只能提示用户拖出来（`tray.note` 已写明）。**文档被用户关掉后图标会自己消失**（约 10 s：用 RestartManager 问系统"还有没有进程占着这个文件"，开着=1 / 关掉=0；实测 Word 9.6 s、Excel 8.6 s、PPT 7.4 s），`save -As` 会把图标重指到新路径，不会留下"AI 协作中"的假象。

**版本 v1.11（2026-10-30）**：新增 **`hint`** —— 接管提示。agent 接管一份用户正开着的文档时，用户原本只会看到"窗口自己滚起来、文字突然变成修订"，不知道是谁在动、怎么停。现在 **`open` 自动给窗口标题/标签页打上「〔AI接管中〕」标记**（`〔AI接管中〕 报告.docx`；纯窗口状态，不写进文档、不落盘），`hint -Doc <路径> -Toast` 再补一个托盘气泡说明"已接管《X》：改动以修订/批注呈现，随时可接受或拒绝"，`hint -Text` 还能刷新状态栏（**表格侧实测可见**；Writer 侧 WPS 只接受写入、界面不渲染，截图仍是页面/字数）；收尾 **`finish` / `close` 自动还原**标题与状态栏。实测 WPS 12.0（2026-10-30）：Writer 的 `doc.ActiveWindow.Caption`、表格的 `wb.Windows(1).Caption` 都可写且直接落到真实窗口标题（`〔AI接管中〕 <文件名> - WPS Office`）。注意 **WPS 12 把文档显示成标签页、从右截断**，所以标记放在名字**前面**：后缀在真实报告的长文件名上会被整段截掉（实测同一像素，等于没打），Writer 的 `Application.StatusBar` 只写不读且界面不渲染（截图实测）、表格的可读写且实测会显示；**PPT 没有可写的单文档标题**（`ActiveWindow.Caption` 只读，`Application.Caption` 是应用级、写进去会顶掉本地化的"WPS 演示"），所以 PPT 侧只给气泡并如实返回 `captionSupported:false` + `limitation`。

**版本 v1.10（2026-10-27）**：把 v1.9 audit 快路径的模式推广到全部"读侧"命令——一次取全文、本地过滤、只在返回/命中处花往返。前提是一天实验证实的**块模型**：WPS 里 `Content.Text` 按 `\r` 切块后**第 k 块就是第 k 段**（表格也不例外：每格是"文本\r+BEL"，BEL 落在下一块开头；表格后首段也带前导 BEL，所以**不能用 BEL 启发式判表内**，表内段区间以 `Table.Range.Paragraphs.Count` 为权威，O(表数) 往返）。统一走 `FastBlocksVerified`：修订非零 / 块数≠段数+1 / 首中末三段抽查不符 → 整体回退旧逐段路径（`-Slow` 可强制），`path`/`textsPath` 字段说明走了哪条。
- **`read -SkipTableCells / -Only` 快路径**：4479 段 / 20 表语料上 `-SkipTableCells -Count 0` **38.6 s → 8.4 s**（快跑还含 ~6 s 开文档；10521 段的真实报告旧路径 111 s，预期 → 10 s 级）；返回 180 段与旧路径**逐字段一致**（i/text/style/list/inTable/table）。注意 `-Only` 若命中大半文档（如 `[0-9]` 命中 3951/4479），逐段 style/list 明细占大头，快慢持平——快路径吃的是**选择性**过滤。
- **`snapshot`/`diff` 快路径**：撤掉 v0.7 的 `tables == 0` 保守门禁（块模型证明带表文档同样成立），4479 段 **22.4 s → 3.2 s（7×）**，快慢两份快照 texts 4479 段**逐字节一致**、digest 相同。
- **`format -Style` / `style -NoNumbering` 改 Find-by-style**：样式定位扫描在 WPS 进程内，往返从 O(段数×2) 降到 O(命中)（万段报告给 40 个标题改格式，从 2 万次往返降到几十次）；任何拒绝回退旧逐段循环（重复套格式幂等）。A/B：命中 7/7 一致、readBack 相同。

**版本 v1.8（2026-10-26）**：按一份真实报告的使用复盘（10521 段 / 32 张表 / 75 页）补齐"表格编号检查"这条链路——复盘结论是**读侧缺能力**：检查用了 6 分钟（22 次 `read` 全扫 4.5 min），改写只花 2 秒。
- 新增 **`word captions`**（只读，一条命令出清单 + 判定）：把每张表与它的题注配对，一次给出**重号 / 同节跳号 / 表号格式混用（点分 `2.4.1` vs 短横 `3.3-1`）/ 题注位置混用（做进表内第 1 行 vs 表外上方）/ 表号与题名之间空格不一 / 缺题注 / 正文悬空引用（`见表3.3-2` 但无此表）**，每条 issue 带段号与改法。实测该报告 **6.4 s** 出结论，当场查出「`表3.3-3` 用了两次」（段 10307、10430，正是要找的问题）；也核对出「32 张表 32 条题注、17 张题名在表内、15 张在表外」，与人工复盘逐个吻合。
- `table -Action scan` 每行新增 **`para`**（表起始段号）：没有它就只能盲试段号，有了它才能定点读题注、直接喂 `table -Action caption -Table n`。
- **修 `search` 的静默错段（高危）**：命中段号原来靠"候选段文本里含这个词"裁决，长表格附近会挑到错邻段，且错段≠0 所以**不会**触发慢路径兜底（实测漏 4 条题注、同一段被重复报 3 次）。现在改用**字符区间校验**（`Range.Start ≤ offset < Range.End`，段区间半开且铺满全文，只可能有一个候选通过），通不过才退回慢扫；结果带 `verified:true`，同段多命中**各有自己的 `at`**，每段 3 条的上限改成显式 `cappedParas`。实测同一文档的段落号与 `read` 逐段扫描**完全一致**。
- **修 `read`/`search` 的 `inTable` 边界**：`Table.Range.End` 是**排他端**，旧判据 `<=` 会把"紧接表格之后的那段正文"标成表内（实测段 10297，为此白跑 2 次 `render`）。现在 `start < end`，且表内段额外带 `table: n`。
- `read` 新增 **`-SkipTableCells` / `-Only <正则>`**：这版文档 10521 段里 **10276 段是表格单元格**，`-Count` 改成"返回多少段"后，一次调用就能把 245 段正文全拿回来（111 s；老办法 22 次调用约 3.5 min）。单段仍要一次 COM 往返，所以这条是"省调用次数与重复开销"，不是数量级提速——数量级在 `captions`。
- `audit` 题注判据改为与 `captions` **共用同一个题注解析器**（标签必须在段首）：正文里"如表3.3-2所示"不再被当成题注；题名做在表内时只报 `table-caption-in-row`，不再同时报 `caption-missing`；图片题注允许在图片后 1–4 段（实测有的图名隔着一个空段和一个"/"残段）。
- 回归：新增语料 `tests/word/captions/`（20 表 / 19 题注 / 4479 段，8 张 35×13 大表，埋重号+跳号+格式混用+悬空引用+表后紧跟正文+缺题注）与 `check_captions.py` 30 条断言全过；旧语料 `report-300` 全链回归（search 13 命中 / revise 10 条 / comment / render / undo / snapshot / diff / handoff / close）全过。

**版本 v1.7（2026-10-25）**：PPT 新增 **`ppt font`** —— 全稿统一字体（`font -Doc -Font 宋体`），逐页扫**组合内部与表格单元格**，只写字体名、不动字号/颜色/加粗/版式。起因：用户要"所有页面改成宋体"，而已有 `format` 一次只能改一个形状且**进不到组合里**（该稿第 2 页就是 5 个组合）。实测 15 页 / 45 形状 / 5 组合 / 1 表格，0 失败；并记下"换字体 → 字身变宽 → 多折行"的连带风险（第 10 页末条曾被挤出页面，需 `format -Size` 收一档）。

**版本 v1.6（2026-10-25）**：`word unit` 增加**上下文守卫 + "可疑碎片"报告 + 脚本段识别**。起因是真报告里有 3 页（实测第 256–258 页）是**公文模板/脚本语法说明**（`[for] … [/for]`、`[File]`、`k~a = 1`、`m1 = 1`／`n2 = 1` 成串赋值），其中的 `km2/m2/m3` 是**变量名**；无守卫的 v1.4 会把它们改成 `km²/m²/m³`（已在真实文档上复现）。现在：
- **只修"挂在数值上"的单位**（前字符＝数字/万/亿/汉字/半全角左括号，或"数字 空格 单位"）；
- **脚本段整段跳过**：段落命中 `[for]`/`[File]`/`k~a`/≥2 条 `x = 1` 赋值即判为模板示例，报告里单列 `scriptPages`（页码），此段的单位一律不动；
- 三类只报不改：`fragments`（孤立 token、后跟 `=`）、`looseFragments`（`n2`/`n3` 缺基名）、`suspects`（`km3` 疑似笔误）；
- 万一在脚本页上仍修了东西（段落特征没覆盖到），会进 `fixedOnScriptPage` 告警。

**版本 v1.5（2026-10-25）**：把"连接"与"动手"分成两挡——新增 **铁律 7**（用户只要"连上 / 接管"时，`status` + `open` 报一句摘要即停，不 `read` 全稿、不 `render`、不 `audit`、不 `close`）；PPT 视觉自检闭环的前提改为"**本轮真的改动过这份稿**"；`audit` 注明人工制作的老稿误报率高、结论以 `render` 目检为准。起因：一次"连上 PPT"被做成了全稿体检，用户干等。
