> 自 v1.29（2026-11-02）从 `SKILL.md` 拆出：原主文档前 74 行版本记录约 1.97 万字符，占整份 skill 的 25.5%，每次加载都白付一次上下文。查「某版改了什么 / 为什么这么设计」看这里；主文档只留当前版本的要点。

**版本 v1.31（2026-11-02）**：**Excel 补"文字更正/日期分组"，PPT 补"成品版式层 phase 1"**（两路并行实现，Lead 独立复跑验收）。
- **Excel `replace`（内存块替换）**：`-Find/[-Replace]（省略=删除）/-Sheet/-Range/-Column/-Whole/-MatchCase/-Regex/-DryRun/-Max/-All`。**绝不用 `Range.Replace`**——WPS 会在刚写进去的文本上二次替换（`P→P-` 得 `P--`，dsh-office 实测）；实现是「一次块读 → 本地单遍替换（游标移到插入串之后）→ 只写真正变化的格」，实测 `PP→P-P-`。返回 `scanned/changed/byColumn/samples/formulaCellsSkipped/numericMatchesLeftAlone/truncated` + `preSnapshot`（`diff -Since`/`restore -Since` 对账与回滚）；**公式格永不写**、**数字/日期格不改成文本**（宁可不改）、`-DryRun` 与实跑同一套判据、不自匹配的规则幂等（实测 `表1→表一` 5→0、`-Whole abc→X` 2→0）。Lead 复跑（6 行含公式列）：`changed:4` 样例 `P→P- / P05→P-05 / XP→XP- / PP→P-P-`，回读公式列仍 `=D2*2`（未被写），第二次 `changed:0`。
- **Excel `pivot -Group` 实测定案**：WPS 12.1.0.29161 **原生支持**按日期分月/季/年（`DataRange.Cells(1,1).Group`，`xlMonth=4/xlQuarter=3/xlYear=2`）。24 行实测：月 `1月110…12月1320` 总计 8580、季 `660/1650/2640/3630`、年 `2024年780/2025年7800`，全与手算一致；返回新增 `groupMode`（`none|native|failed`）+ `group{field,by,mode}`，并**回读 `RowRange` 行项数**校验（某些列连异常都不抛，没变少即判 failed）；文本日期实测抛「选定区域不能分组。」→ `failed` + 辅助列降级配方（`=YEAR()/TEXT(日期,"yyyy-mm")/"Q"&ROUNDUP(MONTH()/3,0)`，辅助列是数据源、建完不能删）。
- **PPT 成品版式层 phase 1（8 档）**：`slide -Preset` 新增 `cards / stats / timeline / process / compare / summary / gallery / split`，数据走 `-Items <json>`（`{"title":…,"cards":[...]}` 等；title 也可放命令行的 `-Title`）。统一：960×540 设计画布按实际页尺寸缩放、标题 28pt（`**强调**`→accent 加粗）+ 色杠 + hairline、页脚、**普通文本框页码「n / N」**（WPS 页码占位符每页显示 "1"，不可用）；正文 14pt，放不下**自动降一档字号**并记 `fontSizeDrops`，降到底仍放不下才报 `overflowWarnings`（形状几何从 WPS 回读）。`theme` 新增 `accent2/surface/cardFill/cardRadius/sectionStyle`（旧主题文件缺字段取默认）。
- **修掉图片裁切的错误路线（Lead 发现）**：子代理最初的 `cover` 用 `PictureFormat.Crop*` 换算，Lead 用 2:1 图独立复跑时 split 图变成 **552×540、x=-36 出页**（`check` blocker: outframe）。根因是 WPS 的 `Crop*` 按**点**解释、且改 `Width/Height` 会把裁切洗掉。改为 **GDI+ 预裁临时副本（按目标宽高比裁，竖图保上 1/5）+ 按框精确插入**，不碰 COM crop；复跑回读 `splitImage l=0 w=480 h=540` 精确、8 页 `check -MinSeverity blocker` = **0**；`gallery` 默认 `contain`（整图不裁、底对齐使图注齐平），`-Fit cover` 才统一裁切。目检两页总览：卡片等高、时间线上下交错、流程箭头、对比双色卡、编号总结、三图正齐平、半页图 edge-to-edge。
- **已知误报（交付时抑制）**：`check` 的 `pagenum` 对普通文本框页码每页报 1 条、`gallery` 图注 10pt 触发 `fontsize`；用 `check -Config '{"suppress":[{"rule":"pagenum"}],"bodyMin":12}'`。另记一条 WPS 坑：写 `TextFrame.AutoSize` 会把文本框压成约 29pt 高。

**版本 v1.30（2026-11-02）**：**Word 排版收尾三件 + 两处"报成功其实没落上"的修正**（上游参照 dsh-office `FillGaps`，算法在 `helper/OfficeHelper.cs:2967-3016`；本次实现在 `scripts/helper/word/FillGaps.cs`）。
- **新命令 `fillgaps`**：图/表放不下整块跳到下一页时，把图/表后面的正文段提到前面填掉上一页底部的留白。参数 `-DryRun`（只报不动；只读文档也能跑）/`-MaxMoves`（每块最多搬几段，默认 8）/`-MinGapPt`（默认 `max(90pt, 文本高度×12%)`）；返回 `moves:[{block,kind,para,page,gap,text}]`。**保守判据**：块前一段必须是正文（不越过标题）、块首行页码必须晚于前一段、块后段不能是空段/题注/图段/表内段、冒号结尾的引导句连带搬。实现坑（已解决并记入 quirks）：① 直接往 `table.Range.Start` 赋 `FormattedText` 会落进**第一个单元格**；② 删表格前那段的段末标记会把表格并进该段、文字又进单元格 ⇒ 正解是在该段段末标记**前** `InsertBefore("\r")` 造空段，再往折叠位置赋值，并用 `Information(12)` 探测"落进表内就撤销放弃"。代价：表格前留一个空段。
- **`noSplitWords` 极性修正**：`ParagraphFormat.WordWrap` 是**反直觉**的——实测（页宽 240pt、左右边距 90pt、20pt Arial、"aa 3700000"）`-1` 才是整词（首行只有 `aa`，数字另起一行）、`0` 是允许拆词（首行 `aa 37`）。v1.29 及更早写成 `v ? 0 : -1`，即**传 `-NoSplitWords` 反而把拆词打开**。现在改为 `v ? -1 : 0` 并**写入后回读**（`noSplitWords=true (readBack=-1)`，不符即 `COM_ERROR`），`insert` 新段 / `table` 单元格 / `caption` 题注**默认整词**；新增 `-SplitWords` 反向开关（`-NoSplitWords:$false` 过不了 `woc.ps1` 的参数往返，会变成字符串 `"false"` 绑不上 switch）。**读图判据**：文本列比 token 窄时（如 60pt 列放 77pt 的 `3700000`），即使 `-1` 也会被行内折断——判"整词与否"看**首行**，不看有没有断行。
- **`table -KeepTogether` 真落上**：旧实现走 `Rows.Item(r).Range.ParagraphFormat`（WPS 上半实现对象、会抛 `0x800A1767`）且 `catch {}` 吞异常 ⇒ 报成功但可能一行没落上；现改为逐行 `Cell(r,1).Range.Select()` + `Selection.MoveEnd(10,1)` 走 `Selection` 写 `KeepWithNext`/`AllowBreakAcrossPages`，并**逐行回读**；失败则整条命令 `ok:false`（`KEEPTOGETHER_FAILED`，`error.detail` 点名行号），成功时返回 `keepTogether:{rowsExpected,rowsSet,readBackFailures,allowBreak}`。为此在 `WpsHelper.cs` 的 `catch (Fail)` 增加 `error.detail` 透传。实测 9 行×10 行文字短页表：改前第 3 行被页底劈开，改后 `rowsSet 8/8`、`allowBreak 9/9`、`readBackFailures []`。
- **验收**：Lead 独立复跑（`%TEMP%` 自建文档 + `render` 目检）——```-SplitWords``` 前后渲染对比确认"首行 `aa` vs `aa 37`"；`table -KeepTogether` 返回 8/8 + 9/9 全回读；`fillgaps` 在自造 3 页稿上 dry-run 报 gap 124.2/210.7 → 实跑 `moved:2`，前后图对照可见空白被正文填上、图表原地、标题未越过；**另在 15 页/20 表真实语料上跑出 `moved:0`，属正常**（密排稿没有 ≥90pt 的图表前留白）。

**版本 v1.28（2026-11-02）**：**PPT 页面标记改为「默认不写文档、按需开启、被 Ctrl+S 污染后自动修复」**（用户质疑 v1.27 的默认行为："用户按 Ctrl+S 徽章就被写进文件，这设计好吗？"——答案是不好，改）。① **`hint` 默认零改动**：只做窗口标题（任务栏可见）+ 气泡 + 可选托盘，返回 `inAppHint` 说明"要界面里看得见请加 `-SlideMark`"。② **`-SlideMark` 显式开启**：逐页贴「〔AI接管中〕」药丸，返回 `slideMarkCount` + `slideMarkWarning`（"这是内容，Ctrl+S 会存进文件"）。③ **自动修复**：helper 记下"贴了标记那一刻的文件 mtime/size"（`%LOCALAPPDATA%\wps-office-cooperate\ppt-slide-mark\<deckHash>.json`），下一条命令若发现**文件被谁保存过**（典型就是用户 Ctrl+S），就剥离徽章→重新保存→再把徽章贴回屏幕，返回 `badgeRepaired:true`（附 `badgeMarksRemoved`）；只读文件给 `badgeDirty`、保存失败给 `badgeRepairFailed`。实测（`tests/ppt/check_hint.py` P6，用裸 COM `Presentation.Save()` 模拟用户 Ctrl+S）：修复后重开文件确认徽章已不在；连续命令不会反复修复。④ 收尾仍是 `hint -Clear` / `finish` / `close`，`save`/`export` 落盘前自动剥离不变。**结论性原则**：PPT 的"界面可见"必然等于"文档被改"（标签页自绘、无状态栏、母版被满版图遮、悬浮窗已否决），所以默认走安全侧，可见性是一次有意识的、可清理的、被自动兜底的动作。

**版本 v1.2（2026-10-25）**：PPT 侧补齐"能交付"这一层——`theme`（主色/字体/页脚/页码，一套 JSON 打底）、预设版式重做（封面色带、章节页色块+大数字、真项目符号、**深色底自动白字**、正文框留白给表格/图片）、`render -Overview`（6 页拼一张图并带页码）、`audit`（文字溢出/字号过小/越界/重叠/图过小/空页机械体检）、`align`/`zorder`/`restore`。
