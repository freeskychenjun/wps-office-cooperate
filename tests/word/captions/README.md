# captions 回归语料（Word 表格题注 / 编号清单）

`wps-office-cooperate` 的 Word 侧要新增「表格题注 / 编号清单」能力，并修两个缺陷
（in-table 题注误判、表后紧跟正文误判）。本目录是这套能力的**回归语料**：一份真实的
.docx，配合一份 `expected.json`，用 WPS 打开后逐条断言即可。

## 产物

| 文件 | 说明 |
|---|---|
| `make_fixture.py` | 幂等生成脚本（python-docx 1.2.0），每次运行整体重建下面两个文件 |
| `captions-fixture.docx` | 语料本体：20 张表（8 张 35×13 大表）、3 章正文、19 条题注 |
| `expected.json` | 期望值：19 条题注（表号/标题/位置/空白/样式）+ 埋入的缺陷清单 |
| `check_captions.py` | 断言脚本（30 条）：跑真机命令并逐条比对 expected.json + 不变量 |
| `README.md` | 本文件 |

## 运行

```powershell
$py = "C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py make_fixture.py          # 重建 docx + expected.json，并打印自检报告
```

脚本是幂等的：重复运行覆盖同名文件，产出**字节一致**（zip 条目时间戳固定为
1980-01-01，core properties 的 created/modified 固定），两次运行 docx 均为
61,586 字节、SHA256 相同。自检不过时进程返回码为 1。

> 注意：**不要用 WPS 打开本目录的 docx 做自检**，会与集成测试抢 WPS 实例。
> 需要人工看版式时用 Word 或另存副本再看。

## 文档结构

标题段「新干枢纽扩容工程可行性研究报告（节选）」+ 3 个一级标题：

- `2 水文`：二级标题 `2.1 基本资料`、`2.2 径流与流量`、`2.4 水位流量关系`
- `3 工程任务和规模`：`3.1 设计洪水`、`3.2 库容与泄流能力`、`3.3 调度规则`
- `4 结论`：`4.1 工程量与投资`、`4.2 结论`

页面 A4，正文宋体五号（10.5 pt）首行缩进两字符，标题黑体；表格为普通网格表。

题注两种写法**交替**：

- `above`：题注是表格**上方紧邻**的独立段落（居中、无首行缩进），题注与表格之间
  **不含空段**；
- `in-table`：题注在表格**第 1 行**，该行用 `rows[0].cells[0].merge(rows[0].cells[-1])`
  合并为 1 格，格内**只有**题注文字（合并遗留的空段落已删除），数据从第 2 行开始。

## 刻意埋入的缺陷 / 场景（逐条对应）

| 缺陷 | 位置 | 说明 |
|---|---|---|
| **重号** | #14、#15 | 两张表都编号 `表3.3-3`（标题不同），应报重复编号 |
| **跳号** | #6 → #7 | 第 2 章 2.4 组只有 `2.4.1` 与 `2.4.3`，缺 `2.4.2`（对应的二级标题也从 2.2 直接到 2.4） |
| **格式混用** | 第 2 章 vs 第 3/4 章 | 第 2 章点分 `2.1.1`；第 3/4 章短横 `3.1-1`、`4.1-1`。应报 inconsistency |
| **空格不一** | #1 / #2 / #3 | #1 两个半角空格、#2 一个全角空格（U+3000）、#3 无空格；其余为两个半角空格 |
| **悬空引用** | 2.4 节末段 | 正文「如表2.9.9所示，各频率设计洪水成果见附表。」文档中不存在 2.9.9，应判 unresolved |

## expected.json 字段

- `doc` / `tables` / `bigTables` / `bigTableSize`：语料基本事实；
- `captions[]`：`table` 表序（按文档顺序 1..20，跳过 19）、`label` 固定「表」、
  `number` 表号、`title` 标题、`pos` `above|in-table`、`gap` 表号与标题之间的空白
  **原样字符串**、`style` 留 `null`；
- `defects`：`duplicates`（重号）、`sequenceGaps`（跳号）、`formatMixed`（点分/短横
  两份编号清单，`3.3-3` 在短横清单中出现两次，对应 #14/#15）、`missingCaptionTables`、
  `spaceMixed`、`danglingReferences`、`resolvedReferences`、`proseAfterTable`
  （`afterTable` + 期望文本前缀）；
- `notes`：一句话说明语料形态。

`expected.json` 由 `make_fixture.py` 与 docx 一同生成，两者始终同源，请勿手工改其一。

## 自检做了什么

`make_fixture.py` 生成后会重新打开 docx（python-docx）并打印报告，核对：

1. 表格数 20、`w:p` 总数落在 4000–6000、大表恰为 #3/4/5/8/9/10/11/19（8 张 35×13）；
2. 逐表行列数、逐表题注文本与规格**逐字相等**、题注位置（above 必须紧邻表格）；
3. #13 之后紧邻元素是段落且正文等于指定句子；#19 上方段落含「如表中数据所示」、
   第 1 行前三格为 项目/单位/数量；
4. 「表3.3-3」出现 2 次、「表2.9.9」出现 1 次、四条正常引用各出现 1 次；
5. 无连续空段。

已知边界：大表单元格内容为连续数字（1..455），小表首行为表头、其余为数字，只为
保证单元格非空，不追求数值合理性。

## 断言脚本（`check_captions.py`）

```powershell
$py = "C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py check_captions.py --verbose     # 30 条断言，退出码 0 = 全过
```

它把语料复制到 `<repo>\.tmp\captions-check\` 再跑（**不动本目录的 docx**），依次驱动
`open` / `captions` / `read`（全量与 `-SkipTableCells`、`-Only`）/ `table -Action scan` /
`search` / `audit -Action caption-missing,table-caption-in-row` / `close`，断言：

- **C1/C2**：`captions` 列出 20 表 19 题注、位置 13/6/1，并与 `expected.json` 逐条比对表号/标题/位置/空白/表序；
  六类缺陷（重号 `3.3-3`、跳号 `2.4.1→2.4.3`、dot/hyphen 混用、空格混用、表 19 无题注、悬空引用 `2.9.9`）各报一次且不多报。
- **B1**：表 13 之后那一段正文的 `inTable` 必须为假（`Table.Range.End` 是排他端）。
- **C3**：`-SkipTableCells` 返回的正好是全量与"表内段"的差集；`-Only <正则>` 与手工筛出的段集合一致。
- **C4**：`scan` 每行的 `para` 必须真的属于该表（`read` 的 `table` 字段对得上）。
- **A1/A2**：`search` 的每个命中 (`para`,`at`) 指向真实命中位置、同段不重复、题注段全部命中（含复盘里漏掉的 4 条）。
- **audit**：只报 1 张"表内也无题注"的表与 6 张"题名在框内"的表（旧判据会多报 9 张图片）。

2026-10-26 实测：30 passed / 0 failed；同一份脚本在 10521 段的真实报告上另做过人工核对
（见 `reference/word-acceptance.md` 的 v1.8 一节）。
